# Сравнительный замер

Цель: на одних и тех же задачах сравнить качество и расход вариантов команды.

## Набор задач

10–15 реальных задач из рабочих проектов, по одной на файл `eval/tasks/NN-name.md`
(шаблон — `_template.md`): проект, стартовый коммит, промпт, заготовленные ответы,
**команды приёмки** (без них задача не принимается). Смесь: ~40% рутина, ~40% средние,
~20% сложные/рискованные.

## Прогон

```sh
team-harness eval eval/tasks --variant A,B,solo   # A: lead Astra, B: lead Kimi, solo: одна Astra сама
team-harness eval eval/tasks/03-x.md --variant A --keep   # оставить worktree для разбора
```

Варианты прогоняются в изолированных git worktree на стартовом коммите, без вопросов
пользователю. Итоговая таблица: принято, среднее время, токены lead, токены по провайдерам.
Все прогоны дописываются в `state/eval/results.jsonl` каталога harness.

## Критерии

- доля принятых задач у A/B не ниже, чем у solo;
- расход квот подписок (openai + kimi) у A/B заметно ниже solo;
- время не хуже solo более чем на 30%.

Если качество падает — смотреть, на каких задачах, и двигать границу между worker и takeover,
а не возвращать работу в lead.

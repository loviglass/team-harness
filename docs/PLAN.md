# План team-harness

## Диагноз (по базе сессий старого harness, 867 сообщений)

- 80% контекста оркестратора (18,3 из 22,8 млн токенов) — ручная работа:
  bash 234, read 114, edit 68 против 30 делегирований. 12 КБ правил «делегируй» не помогли.
- Делегирование дешёвое: бриф ~1,5 тыс. символов, ответ ~0,6 тыс.
- Кэш работает (93–98%), базовый промпт ~11 тыс. Дорого не одно обращение, а
  растущая история с выводом инструментов в контексте дорогой модели.
- Astra в роли оркестратора делегировала лучше всех (ручная работа 28% против 82–94%).

## Принципы (из исследований и данных)

1. Делегирование обеспечивается отсутствием инструментов, а не промптом
   (Roo Code Orchestrator, Claude Code delegate mode).
2. Один писатель на рабочее дерево (Cognition).
3. Качество держат детерминированные проверки (тесты/typecheck/lint) в цикле исполнителя;
   сильная модель — для диагноза и ревью диффа (Olausson et al., Large Language Monkeys).
4. Эскалация по детерминированному признаку (две неудачи одной проверки), а не по
   самооценке слабой модели (Cognition, smart friend).
5. Возвраты субагентов короткие и структурированные; полные логи — на диске.
6. Модель внутри сессии не переключается; промпты ролей стабильны (prompt caching).
7. Ревью — в свежем контексте, только бриф + дифф.

## Роли

| Роль | Модель | Инструменты |
|---|---|---|
| lead | Astra (lead-kimi — Kimi для A/B) | read/grep/glob, task, git status/diff --stat/log; без edit/bash/web |
| worker | DeepSeek Flash/high | всё, кроме task/web; единственный писатель |
| takeover | Kimi K3.1 Pro/high | как worker; после двух неудач worker или для связанных изменений |
| scout | DeepSeek Flash/low | только чтение + безопасные git/rg |
| reviewer | Astra/high | только чтение + git diff/show/log; 15 шагов |
| advisor | Astra/high | без инструментов, 1 шаг |
| compaction/title/summary | DeepSeek Flash | — |

Интерфейс: интерактивный TUI OpenCode, агент по умолчанию — lead.

## Этапы

| # | Этап | Критерий |
|---|---|---|
| 0 | Набор 10–15 реальных задач, метрики (`metrics/`, `eval/`) | базовые цифры старого harness |
| 1 | Нативные агенты OpenCode без Slim, lead без инструментов правки (**сделано**) | lead_ctx ≥3× меньше, качество не ниже |
| 2 | Runner: машина состояний (бриф → worker → gate → эскалация → review → отчёт) как инструмент lead; gate из `.harness.yaml` проекта | ≥4× меньше токенов умной модели |
| 3 | Сравнение движков на том же наборе: OpenCode vs pi | выбор по цифрам |
| 4 | Поставка: install.sh/ps1, автообновление по тегам (**сделано**); CI совместимости с новыми версиями OpenCode | обновление конфига без релиза |
| 5 | Архивировать opencode-team-harness после миграции команды | — |

Из старого репо переносится по необходимости: опрос квот (`quota.go`) и
`exec`/`monitor` для внешнего координатора.

Не переносится: Slim, astra-budget, stable-skills, compaction-budget, fingerprint-блокировка,
bundle с node_modules, сборка Go на машине сотрудника.

## Известные риски

- Lead без bash не может сам запустить тесты: доказательство — отчёт worker с кодами
  выхода. На этапе 2 runner запускает gate сам, независимо от worker.
- Возможны «пустые» передачи (Roo Code #3362): lead просит scout прочитать файл,
  который проще прочитать самому. Lead разрешено читать узкие диапазоны.
- Лимиты возвратов субагентов на этапе 1 заданы только промптом; на этапе 2 — кодом.
- OpenCode 2.x меняет субагентов (всегда фоновые, #64096). Пин 1.19.5 до проверки.
